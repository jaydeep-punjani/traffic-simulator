# Audit, November 2026

Scope: the whole repository at commit `e01274d` (first complete build). Goal: find bugs, security issues and departures
from good practice, fix the confirmed ones, and document the result.

## Method

1. **Tooling baseline.** `ruff` (broad rule set), `mypy`, `pytest --cov` and `pip-audit` on the original commit.
2. **Independent review.** Three code-review agents from different model families (Claude, GPT, Gemini) received the
   same brief covering security, concurrency, simulation correctness, Segment spec conformance and packaging.
3. **Verification.** Every reported issue was checked against the code before being accepted. Disproved items are listed
   under [Disputed](#disputed).
4. **Remediation.** Each confirmed issue was fixed, and a regression test was added where the behaviour is testable
   (`tests/test_audit_regressions.py`).
5. **Re-verification.** Full test suite on Python 3.10 and 3.15, lint, type check, wheel install from outside the
   source tree, and the 100k-session end-to-end run against the mock collector.

## Findings and fixes

Severity reflects impact for this tool's intended use: a local operator tool that sends synthetic traffic to a
collector with real write keys.

### High

| # | Area | Finding | Fix |
|---|---|---|---|
| H1 | API | No CSRF protection. Any web page open in the operator's browser could `POST` to `http://127.0.0.1:8000` and start or alter runs that send traffic with the configured write keys. The WebSocket accepted any origin. | Middleware rejects non-GET requests whose `Origin` does not match `Host` (403). The WebSocket handshake is rejected (HTTP 403) on mismatch. |
| H2 | API | Scenario ids and `verticals.*.catalog` from API requests were resolved as file paths, so a request could read YAML-parsable files outside the project. | API accepts identifiers only (`[A-Za-z0-9_-]{1,64}`); file paths are a CLI-only feature (`allow_path=False`). |
| H3 | API, config | YAML aliases allowed a "billion laughs" document to expand into gigabytes. No limits on YAML size, overrides, speed, concurrency or overlay magnitudes. | `StrictSafeLoader` rejects anchors/aliases. Size and count limits on requests; bounds on every numeric field (see [operations.md#security](operations.md#security)). |
| H4 | Emitter | The Segment SDK drops messages over 32 KB without calling `task_done()`, so draining the queue at stop could hang forever and the drop was invisible. | `SimConsumer.next()` acknowledges and counts them as `oversize`. Drain is bounded; anything left is reported as `undelivered`. |
| H5 | Mock collector | Unbounded request bodies and unbounded gzip decompression (zip bomb). | 4 MB body cap (413), 16 MB decompression cap (400), invalid gzip → 400. |
| H6 | Dashboard | Chart.js was loaded from a CDN with no integrity check, and several values were inserted with `innerHTML`. | Chart.js 4.4.4 vendored with recorded SHA-256 and licence. All dynamic text escaped or set with `textContent`. Strict CSP with no inline scripts or styles. |

### Medium

| # | Area | Finding | Fix |
|---|---|---|---|
| M1 | API | Two concurrent `POST /api/runs` could both start a run. Control endpoints on a finished run returned 200 and did nothing. | `asyncio.Lock` around start; 409 for a second start and for controls on an inactive run. |
| M2 | Runner | A worker that never exited (for example blocked on a dead collector) kept the run in `stopping` forever. | Workers are reaped `drain_timeout + 15 s` after stop and the run records an error. Time series streamed to `timeseries.jsonl` during the run. |
| M3 | Worker | While paused, the worker loop busy-waited at 100 % CPU per worker. | Sleeps 50 ms per iteration while paused; control messages are still read every iteration. |
| M4 | Worker | Warm-start sessions all drew fresh lifetimes, so the warm population ended almost together around the mean session length, causing a dip and re-spike. | Length-biased residual lifetimes, matching a steady-state population. |
| M5 | Identity | The same user could be in two concurrent sessions; overflow users were minted without bound; signup state was lost between sessions. | `UserPool` tracks active users, recycles overflow ids (bounded by peak concurrency) and persists per-user state such as `signed_up_at` and installed games. |
| M6 | Gaming | `Game Installed` and the tutorial fired on every session of a launch, not once per player. | Installs are persisted per user; first sessions follow `new_player_share` (launch) or `new_player_rate` (otherwise). |
| M7 | Planner | Region-scoped overlays applied their journey bias to every region. | Effects are computed per cohort including region. |
| M8 | Planner | Peak estimation sampled coarsely and could miss short overlays, under-sizing workers. | Sampling also includes the start, middle and end of every overlay's plateau. |
| M9 | Clock | `time.time()` made sim time jump on NTP adjustments. | `time.monotonic()`, which is system-wide, so all processes share the anchor. |
| M10 | Scheduler | Stale heap entries could fire a session twice after rescheduling; heap ties compared session objects. | Heap of `(time, session_id)` plus an index of live entries. |
| M11 | Stats | Aggregator state was read by the API thread while being written by the receiver thread. | `RLock` around all reads and writes; snapshots for the series. |
| M12 | Config | `${VAR:-default}` ignored the default when the variable was set but empty; `redacted()` showed key prefixes and suffixes. | Default applies when unset or empty; keys fully masked. `--host` now also overrides an empty configured host. |
| M13 | Timestamps | Accelerated runs from `now` silently stamped events hours into the future. | CLI and dashboard warn with the size of the lead and the fix (`start_at` in the past). |
| M14 | Packaging | The wheel omitted scenarios, catalogs and the example config, and wrote runs into `site-packages`. | Data bundled under `trafficsim/_data`; runs go to `./runs` (or `TRAFFICSIM_RUNS_DIR`) when installed. |

### Low

| # | Area | Finding | Fix |
|---|---|---|---|
| L1 | Identity | Traits used `first_name`/`last_name` and a numeric `created_at`, not Segment's reserved `firstName`, `lastName`, `address.country` and ISO-8601 `createdAt`. | Reserved trait names. |
| L2 | Contexts | Devices could report an OS older than their launch OS; Android build ids did not match the OS; iPads reported as iPhones; PS5 width and height chosen independently. | OS filtered by device launch version; matching build ids; iPadOS user agent; PS5 resolutions as valid pairs. |
| L3 | Ecom | `sign_in` was unreachable in the journey; `list_id` reported `browse` for search results. | Journey edge added; unreachable states now fail validation. `list_id` is correct. |
| L4 | Patterns | Diurnal hour index could reach 24 for some fractional offsets. | Wrapped index. |
| L5 | Stats | Funnel conversion divided by zero when the first step had no events. | Rate 0. |
| L6 | API | Validation errors echoed the submitted values. | Errors omit input values. |
| L7 | CLI | On Python < 3.12, `--start-at -24h` failed because argparse read `-24h` as an option. Found during re-verification on 3.10. | The CLI joins negative values for `--start-at`. |
| L8 | Code quality | 217 ruff findings (among them unused imports, files opened without an explicit encoding, and simplifiable constructs), 19 mypy errors, no formatter, unbounded dependency ranges. | Clean ruff (with documented ignores), mypy with the pydantic plugin, `ruff format`, bounded dependency ranges, dev extras. |
| L9 | Docs | README showed `params: {titles: …}` (the real key is `content_titles`) and claimed Python ≥ 3.11. | Corrected; reference docs added. |

## Disputed

Reported by at least one reviewer and disproved on inspection:

- **Path traversal in `/api/runs/{rid}/files/{name}`.** The resolved path is checked to be inside the runs directory and
  `rid` must be an identifier.
- **Further XSS sinks in the dashboard.** The remaining `innerHTML` uses already passed values through `escapeHtml`.
- **Clock, timezone and Little's-law arithmetic errors.** Re-derived by hand; the formulas are correct.
- **`WorkerStats` rebinding its dictionaries loses data.** The rebinding happens after the snapshot is sent, which is
  intentional.
- **SDK `_requeue` double-counts events.** Counting happens only in `request()` after success, so requeues do not
  double-count.
- **`Order Completed` revenue semantics.** Matches the E-commerce Spec (`revenue` excludes shipping and tax; `total`
  includes them).
- One reviewer cited test files that do not exist; those items were discarded.

## Known limitations

- The dashboard has no authentication. It binds to localhost by default; see [operations.md#security](operations.md#security).
- Daylight saving time is not modelled; regions use fixed UTC offsets.
- The mock collector counts events by `"messageId"` occurrences rather than parsing JSON. This is exact for SDK
  output but is a test tool, not a validator.
- `events_per_sec_cap` is split evenly across workers, so a skewed shard can run below the global cap.
